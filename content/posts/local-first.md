对于一个简单的阅读收藏功能，是否一定要先建立账号系统？未必。浏览器存储可以让功能快速可用，但我们也需要诚实说明它的边界。

## 先把数据留在手边

主题偏好、阅读字号和小型草稿适合使用浏览器本地存储。用户点击之后就能得到反馈，不需要等待网络请求。

```javascript
function saveDraft(text) {
  try {
    localStorage.setItem('draft', text);
    return { ok: true };
  } catch {
    return { ok: false, reason: '本地存储不可用' };
  }
}
```

这里的 `try/catch` 不是装饰。在存储空间不足或浏览器限制存储时，写入可能失败。界面应该告诉用户发生了什么，避免承诺实际上没有完成的保存。

## 本地保存不是云端备份

同一个人换了浏览器，通常不会看到同一份数据。清除网站数据也会删除收藏与草稿。隐私浏览模式下，数据可能在会话结束后消失。

因此，“仅保存在当前浏览器”应该出现在功能附近，而不是藏在很长的说明里。

## 给数据一条离开的路

即使一个工具非常小，导出也很有价值。草稿可以下载为 Markdown，收藏可以导出为 JSON。开放、可读的格式让内容不会被某个页面锁住。

导出不等于备份系统，但它提供了一条简单可靠的路径。用户可以把文件放进自己熟悉的同步目录，或交给其他工具继续处理。

## 什么时候需要服务器

当用户真正需要跨设备同步、多人协作或可靠的历史恢复时，服务端就有了明确的用途。这些需求意味着身份、权限、冲突与恢复流程都需要一起考虑。

先把本地体验做清楚，再基于真实需要扩展。一个小功能，也可以把自己的责任边界说得很明白。
