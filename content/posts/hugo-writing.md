这个博客采用静态生成的方式：文章保存在 Markdown 文件里，Hugo 在构建时把它们转换成 HTML。读者访问时，不需要等待服务器查询文章数据库。

## 让内容独立于页面

文章放在 `content/posts/`，模板放在 `layouts/`。这种分离让换一套界面不必重写所有文字，也让内容能被其他工具读取。

在文章开头，用 front matter 描述标题、日期与标签：

```yaml
---
title: 今天的小发现
date: 2026-10-07T10:00:00+08:00
description: 用一句话介绍这篇文章。
categories: [生活]
tags: [日常, 随笔]
draft: false
---
```

写作时可以先设为草稿，本地预览时包含草稿，准备好后再发布。

## 本地先看一眼

```bash
hugo server -D
```

打开终端给出的本地地址，检查标题、段落、代码和图片。对一篇普通文章，重点不是每一个像素，而是有没有内容缺失、图片说明是否准确、链接是否能到达预期位置。

本项目使用 Hugo 0.160.1 做构建验证。具体命令与模板规则以 [Hugo 官方文档](https://gohugo.io/documentation/) 为准。

## 发布前的三个检查

1. **内容**：是否还有不该公开的草稿或个人信息？
2. **链接**：站内路径、RSS 和 canonical 是否指向正确网址？
3. **构建**：生成过程中是否出现错误，输出目录是否完整？

本站的发布网址统一为 `https://st0lyp1n.github.io/`。GitHub Actions 完成构建后把静态输出交给 Pages。

## 把维护成本留在低处

每一个依赖都可能带来更新和兼容成本。对于个人博客，先使用平台已经提供的能力：静态页面、浏览器搜索、RSS 和简单的本地偏好设置。

如果以后需要多人编辑、复杂检索或实时数据，再针对实际需求扩展。内容先持续增长，工具再跟着长大。
